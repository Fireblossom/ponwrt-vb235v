# M79 v2: permanent TX worker shutdown

This is an additive correction to frozen M79 v1, commit `3fdc6a21`. It changes one production call in `mt7996_unregister_device()`: `mt76_worker_disable()` becomes `mt76_worker_teardown()`, with an explanatory comment. Package patch 122 applies after unchanged patches 120 and 121. No calibration, NAPI, IRQ, PCIe or firmware-reset code is changed by v2.

The parent hardware test cold-booted v1, released both native IRQ vector sets on primary-only unbind, and rebound valid private calibration with a wiphy within three seconds. However, unbind emitted `WARNING: kthread_park` with `lr: mt76_dma_cleanup`. Evidence is `offline-analysis/m79-wifi-primary-rebind/cycle-1-private.log` and its report. This is a real v1 regression and fails clean-teardown acceptance even though rebind succeeded.

The v1 unload path parked the TX worker before IRQ shutdown. Common `mt76_dma_cleanup()` then parked that same worker again. Linux 6.18.60 `kthread_park()` explicitly warns and returns `-EBUSY` if `KTHREAD_SHOULD_PARK` is already set. The original host model made worker-disable a no-op and mocked DMA cleanup without its common worker-disable call, so it could not detect this failure.

Permanent unregistration never resumes this worker. The existing `mt76_worker_teardown()` helper calls `kthread_stop()` and sets `w->task = NULL`. The later common DMA worker-disable and final `mt76_free_device()` teardown both return immediately on NULL. This preserves stopping the TX producer before NAPI/IRQ/DMA teardown, handles an already parked worker, and avoids broad changes to the common worker API. The whole unregister/free operation is not an API for repeated calls on an already freed device; the stop sequence within that operation is safe across its multiple owners.

NAPI ownership was audited alongside it. MT7996 unregister disables RX NAPI once; common DMA cleanup only deletes those RX NAPI contexts. Unregister disables and deletes TX NAPI, which clears `NAPI_STATE_LISTED`; common DMA cleanup's existing LISTED guard therefore skips the second TX disable/delete. No second production NAPI stop was found in this chain, and no NAPI behavior is changed by v2.

`test_host_v2.py V1_SOURCE V2_SOURCE OUTPUT` retains the v1 resource/IRQ/work checks but now extracts the actual `mt76_worker_disable()` and `mt76_worker_teardown()` inline helpers, actual common `mt76_dma_cleanup()`, and actual `mt76_free_device()` body. Mock `kthread_park()` implements the kernel's already-parked rejection; mock stop terminates an unparked or already parked task. NAPI tracks enabled/listed states and rejects repeated disable/delete, including after deletion leaves its device pointer non-NULL as the real kernel does.

The enhanced ASan/UBSan model runs 1,440 success/failure/partial-init/HIF2/WED/unbind/rebind combinations, including initially parked and unparked workers. V2 completes with zero park calls and 576 synchronous worker stops. Frozen v1 fails at the second park with one prior successful park, reproducing the live contract violation. Mutations adding TX or RX duplicate NAPI stop each fail, and all three original vector/handler/reset-work mutations remain detected. These tests do not reproduce kernel scheduling or actual DMA hardware.

All outputs are isolated under `/home/duanx/m79-wifi-recovery-v2`; the shared build/kernel/staging tree is read-only. WED, NPU and combined optional branches also compile in 12 changed-unit checks. This is source/ABI validation, not backend hardware qualification. Exact output paths, hashes and limitations are in `offline-compile-report.json` and `findings/wifi-recovery-m79-v2.json`.
